# GitHub connection implementation plan

**Goal:** Connect the owner's GitHub account, expose GitHub tools through existing permissions, and admit native GitHub events into shared autonomous decision turns.

**Architecture:** GitHub App OAuth with PKCE and owner confirmation saves encrypted user credentials in McpConnections. GitHub's official hosted MCP supplies the live tool catalog. A native signature-verifying adapter publishes bounded WakeupEvents; the shared ingress thread owns admission and decision policy.

**Tech stack:** TypeScript, Hono, existing SQLite encryption and MCP broker, Vitest.

**Spec:** The agreed contract in this thread and the ingress thread: `publish(event: WakeupEvent): Promise<{accepted:boolean;duplicate:boolean}>`; source `github`; envelope at most 16,384 UTF-8 bytes; no payload-derived authority. Shared implementation is separately owned.

## Constraints

- All tools start disabled. Existing read/approval permissions, receipts and generation invalidation remain authoritative.
- Verify OAuth account numeric ID, state, principal, redirect and connection generation. Use expiring GitHub App user tokens and host-only refresh; do not retry ambiguous refreshes.
- Authenticate webhook raw bytes before parsing. Event/delivery headers are validated transport metadata, not covered by HMAC.
- Preserve lookup identifiers and provider timestamps; explicitly identify omitted context. Never retain transport credentials.
- Failed admission returns non-2xx. GitHub needs explicit redelivery; acceptance does not mean an action ran.
- No production configuration, app registration or live consent is claimed by local implementation.

## Local verification

OAuth, ingress and actual MCP wrapper fixtures pass, including permission,
reconnect, disconnect and concurrent-refresh races. The existing MCP regression
suite passed. Formatter, lint and typecheck passed; Oracle follow-up found no
blockers after separating credential generation from consent revision. Browser
fixtures exercised save confirmation and saved/pending states, with desktop and
mobile screenshots inspected. Live GitHub consent and actions are not verified.
The broader actor suite is not green; representative release-inspection and
memory-scope failures also reproduce on an untouched archive of the starting
GitHub main. They are not fixed or suppressed by this feature.
