## Metadata dispatch boundary

The dispatcher accepts only registered metadata definitions on an execution turn
with the original host context and operation ID. Each invocation captures a fresh
ID list and intersects it with the original delegation ceiling, current module
configuration and available host ports. A newly enabled module cannot expand old
queued work. Interaction, event-decision, notification-only, contextless and final
report-only turns receive no modular action grant.

`Dependencies.capabilityInspection` is a named full-metadata binding, distinct from
transport-sized direct inspection. Missing bindings are unavailable; there is no
legacy-reader fallback or fabricated source. The mounted reader fixes the original
event/signal and checks current admission, reader identity and delivery permission
at the host call, including after a handler's preparation awaits. It withholds late
results after revocation and awaits the raw callback without a new timeout or retry.
Observations are complete through 64 KiB UTF-8; larger output returns a terminal
unavailable receipt, never truncated JSON. This is an output-size bound, not an
inference token quota or monetary admission cap.

Disposable boundary verification reproduced an initial post-preparation dispatch
gap, then verified no reader call after revocation, configuration disable, port
removal/replacement or delivery revocation. The 34-case probe also covers roles,
strict schemas, missing ceilings, late data, error redaction and UTF-8 limits.
Seven actual prompt paths select all 28 knowledge slots without granting extra
actions. Oracle follow-up found no remaining blocker after the port-level fence.
These local checks are not a live June feature or deployment attestation.

## Named task projection boundary

`Dependencies.capabilityTasks` optionally supplies the existing `TaskViewPort`.
Its mounted `inspect` accepts only the original invocation object, pins the
port and reader identities, and checks the worker's source/deletion/current and
delivery predicates before and after awaiting the raw reader. Late results are
withheld; cancellation does not release a still-pending callback. Without the
port, original invocation or injected process `effectRuntime`, there is no
callable substitute, actor RPC or KV lookup. The existing inspection mount does
not require this new runtime binding.

The task adapter keeps its Promise-shaped contract and runs one named Effect on
the injected runtime, never a per-call runtime or module singleton. Its
uninterruptible Promise boundary keeps occupancy until the original reader
settles, while passing the original invocation and its signal to the reader.
Signal/current checks and the actual reader call stay in the same callback;
cancellation cannot publish late output. Reader failures map to a fixed tagged
message, never raw errors. In Effect 4.0.2 that bounded failure also wins over a
pending interruption when the final cause becomes a Promise rejection. Callers
classify cancellation from the original signal, not the rejection tag. The span
records an error status without the raw message; no failure-to-interruption
remapping changes the legacy contract. There are no Effect retries, timeout races
or changes to registry/raw-operation lifetime.
Production wiring is C01's separate slice: inject the instance already created
by `main.ts`. Missing wiring remains unavailable, never a fallback.

The session host passes its original Rivet `abortSignal`, and the activity actor
receives that same process `effectRuntime` dependency. The registry now connects
S02's exact-assignment catalog stop/status methods through conversation actions
and the existing activity owner. Missing optional callbacks return false/false;
activity lookup does not create an absent owner. An action can still wake an
existing sleeping owner: this is stop routing, not the task projection's no-wake
reader. The bindings do not allocate roots, retire unknown work or mount an
IntentPort or model-callable cancellation command.

Disposable real-registry/native-engine verification reproduced the missing

## F002 remains a separate root integration

K2 signatures alone do not provide a root owner, generation, durable first-dispatch
claim, descendant cancellation or immutable settlement. No IntentPort is mounted
by this slice. Preserve Rivet's lifecycle, serializer admission, raw settlement,
keep-awake wrappers and journal names/order when adding those owner-local hooks.
Do not invent intent versions, backfill legacy work or use job IDs as authority.

Legacy notification generation still calls `model.reply` directly. Aggregate
completion does not establish raw provider settlement; S02's queued-only stop
proof is not a strict fence for an admitted notification. Root acceptance must
include unknown provider/delivery outcomes and restart evidence, not reinterpret
completed as settled. Async `current` or `begin` RPCs cannot substitute for a
synchronous local check after preparation and immediately before dispatch.
