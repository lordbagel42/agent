## First increment: existing broker and MCP policy

F007/F008/F010 receive bounded hardening, not full parity acceptance. F012 gains
explicit processing uncertainty in the existing June-callable `mcpPermission`
inspection. No accounts, scopes, providers, credentials or privacy profiles are
enrolled; existing granted reads remain callable without per-call confirmation.

Canonical broker action snapshots are deeply frozen before grant matching and
credential resolution. MCP tool dispatch and transient result disclosure recheck
the saved connection revision, connected state and current expiry. Successful
host GitHub refresh remains supported; it does not change tool permission.
Revoked/expired results cannot enter another model round or escape synthesis.
Confirmed receipts survive result withholding; consumed unknown operations never
reopen. Initialization/discovery/cleanup traffic is not a new revocation fence.

`mcpPermission` reports saved expiry plus unknown retention/training/region and
unverified entitlement without contacting a provider or obtaining credentials.
Disconnect and retained-data deletion remain separate. Source text, catalog
annotations and returned instructions cannot change saved host grants.

## Contracts and outstanding gates

K3 v1 is coordinated with C01: reuse `ToolAction`/`Receipt`, bind authenticated
source/audience, operation, account, exact artifact and expiry, and require the
current intent reference for admission/recheck. The host-context-bound port's
credential callback is one-use and nonserializable. No K3 implementation/default
port or legacy-grant reinterpretation ships in this increment.

K8 v1 carries `POLICY_KNOWLEDGE` through the S03-owned prompt section. Interaction
agents delegate, execution/event decisions use only their exposed capabilities,
and notifications remain report-only. The existing MCP wrapper also supplies the
same guidance to its tool loop.

Full F007/F008/F010 still require F002 current-intent/source fences and C01/C02
integration. F012 privacy-profile enforcement is not implemented. D2/D4/D6 still
gate new scope/provider/privacy choices. Existing authorized subscription/included
inference has no token quota; separately metered API billing is not assumed free.
The owner's later no-spending instruction, including Stripe Link for now, requires
separate host monetary classification/enforcement with S04. External paid effects
cannot relabel themselves as inference. This increment adds neither budgets nor
paid authority and does not claim a global spend fence.

validation, MCP SDK and a pinned-CA local HTTPS fixture. Only synthetic accounts
and credentials in private temporary databases are used, never live enrollment.
The unchanged code reproduced post-admission nested-action substitution, expired
read/effect dispatch and late result/synthesis disclosure. The changed code denies
those cases while preserving exact grants and refreshed GitHub calls.

Controls exercise changed body/recipient/account/audience, revocation during
credential resolution, expired/stopped operations, consumed-grant replay,
disconnect during discovery, changed contracts, disabled tools despite hostile
source instructions, and credential-canary exclusion from model/receipts/audit.

Slack model behavior and full new parity intent fences are not established by
this synthetic workflow.

effect-result synthesis-expiry control is included in disposable validation.
Formatter, lint and typecheck passed before publication. Deployment and final
all-prompt/loaded-release evidence will be recorded after publication; source
support is not a live attestation.
