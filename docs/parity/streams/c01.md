## Wave-0 internal contracts v1

`src/capabilities/contracts.ts` defines K0/K2–K7 and the common K9 software gate.
`catalog.ts` statically imports 28 source-owned module slots. `config.ts`
composes their strict schemas into optional root `moduleConfig`; legacy broker
`capabilities.directory` is unchanged. Missing configuration defaults software on,
not permission or readiness. Explicit `enabled:false` is protected configuration,
not an ordinary settings preference. Do not add `moduleConfig` to live config just
to spell defaults: existing whole-config settings baseline rules still apply.

Each domain owns its `src/capabilities/modules/sNN.ts` after scaffold publication:
export `configSchema` (extend the strict common schema) and `definitions`.
Use `defineCapability` for schema-derived command validation and named host ports.
Missing required ports produce safe operator prerequisites without invoking the
availability reader or factory. No K2–K7 fallback implementation is installed.
Scope-bound intent/policy ports must not authorize by ID alone. K3 effect admission
requires current intent; credential release rechecks source/intent/revocation.
K4 is monetary-effect-only and inert: a reservation is not payment permission.

C02 owns K1 runtime dispatch and K8 prompt assembly. The agreed first real command
is `s01.capability-inspection`, strict `{action:"inspect"}`, metadata/execution
only. Its named inspection port reads the existing `capability-matrix`; legacy
inspection remains available unchanged. C02 intersects captured/current IDs and
requires genuine host execution context; C01 supplies additive reply validation
and main configuration propagation. Interaction/notification turns gain no action.

K7 observations use `observedAt`, nullable revision/expiry, explicit freshness,
scope/source and optional safe reason. All seven axes are independent; S01's
projection must downgrade missing, stale or future evidence to unknown and preserve
legacy rows. Host mounting is not enrollment, health or live attestation.

## Additive provider boundary and host configuration

The provider accepts a registered `capability:{id,command}` only under an explicit
captured ID ceiling with matching execution/execution or legacy-role/event-decision
classification. Missing grants, wrong turns and unknown IDs remove the wire field
and reject even raw null. The first runtime slice remains narrower: execution-only
metadata, assembled by C02 from genuine execution context. Accepted commands obey
the existing one-directive and empty-text rules; legacy replies remain unchanged.
Main forwards `moduleConfig` through `Dependencies.capabilityConfig` so explicit
false can reach capture and dispatch rather than becoming a source-only promise.

Disposable checks exercise all 20 role/turn pairs, cross-turn IDs, absent/empty
ceilings, extra model-selected authority fields, strict JSON Schema, mixed actions,
legacy inspection, and the provider's reply/settlement lifecycle using a local
transport. The first transport fixture omitted a required completed-message status;
correcting the fixture made the full probe pass without loosening provider parsing.
No remote inference or real charge was used. Actual runtime dispatch and real
inspection registration remain C02/S01 work, not proven by this provider probe.

K2 now includes host-only `begin`/`settle` signatures: first admission persists in
the existing owner's journal, lost acknowledgments never permit replay, and async
checks never replace the owner's synchronous dispatch fence. Original outcomes
can settle after intent changes; unknowns retain holds. No implementation is
mounted and no new durable store or migration is introduced.
