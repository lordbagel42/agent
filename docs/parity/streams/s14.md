# S14 — workflows, research and routines

Owner: [S14 implementation thread](https://ampcode.com/threads/T-01a125a1-4116-75d8-a052-220d1369fee1).
Scope: bounded F002 support in existing workflow/research owners before
F031/F034 or later monitors. No second scheduler or journal service.

## Current increment — local intent and settlement

This increment carries an owner-local synchronous current check into workflow
tools, waits for model settlement separately from its answer, and preserves
content-free operation receipts after cancellation/forgetting. A stopped run
cannot publish a late result, but an already-confirmed effect remains confirmed.
Research controls advance a local generation; an old batch cannot become current
again through pause/resume. Unknown tool evidence is sticky and blocks further
batch actions rather than being overwritten by a later confirmation.

Confirmed pre-dispatch model funding denials pause research with the exact
`billing_unverified` or `owner_spending_prohibited` reason instead of scheduling
the same denied attempt again. This requires a nonretryable host `ModelError`
and `not_started` raw settlement; unknown IO still retains its hold. A later
explicit resume does not waive the actual provider's funding policy.

Workflow receipts add `not_started` and `failed` alongside the existing
`started`, `completed`, and `unknown`. Existing readers already refuse to replay
any non-completed receipt. Research's optional `intentVersion` treats absent
legacy state as generation zero. Neither change renames/reorders native journal
steps or rewrites old receipts into successful outcomes. Rivet-owned outer
lifecycle/timeout/error/admission wrappers remain with their existing owner.

K2 v1 types come from `src/capabilities/contracts.ts`; K8 uses the handed-over
`src/runtime/prompt-sections/s14.ts`. S02/C02 agreed that admission persists in
the existing owner, then rechecks local state immediately before dispatch.
An asynchronous current RPC is not that fence. Optional ancestor intent binding
is provenance only, not a grant or a backfilled legacy identity.

## Evidence and remaining gates

10 October 2026: disposable component probes reproduced five baseline failures,
then passed after the change: stale notification, search and agent enqueue,
workflow answer before raw settlement, and research unknown evidence followed by
a confirmed receipt. Both funding-denial codes also failed before and passed
after; the negative control retains unknown raw settlement over an apparent
policy denial. Actual `buildModelRequest` checks cover interaction, execution,
event decision, notification-only and completion without granting missing tools.

Oracle identified stale native signal consumption that could restore a forgotten
payload after revoke. The callback now checks local state before the write and
after its awaits before returning content; focused follow-up found no blocker in
the two reported interleavings. The subsequent funding/stop/unknown review also
found no material issue.

At 13:26–13:27 UTC the same component checks and six real standalone Rivet-engine
cases passed on the rebased increment: normal send; cancellation retaining a
confirmed send without its late value; revoke retaining unknown without payload;
raw model occupancy through cancellation; a funding denial pausing without retry
after advancing the clock; and research unknown occupancy surviving confirmation
and stop. Only disposable local provider/channel fixtures ran. The expected
unknown case latched the disposable lifecycle; shutdown emitted transaction-closed
warnings. The harness closed its registry/client, stopped its exact engine,
removed only its disposable data, and exited successfully. These checks do not
establish production billing classifications or live feature acceptance.

Formatter, lint and typecheck passed under the runner's shared validation lock.
The three-CPU runner still requires serialized heavy checks. The current source
lock and existing immutable dependency tree differ only by esbuild 0.28.2 moving
from development to runtime dependencies; its installed version is unchanged.
The coordinator independently reconciled all package, snapshot, patch and importer
bindings. This is compatibility evidence, not a fresh frozen-install claim. No
new ordinary tests or dependencies have been added.

This is not full F002, a global no-spend fence, or feature/live acceptance.
Conversation/delegation begin/settle adapters and descendant invalidation belong
to C02, wakeup/catalog integration to S02. Provider/MCP/search funding guards
belong to C01/S03/S04; S14 must verify these actual lower boundaries without an
invented inference cap. Channel preparation and already-enqueued agent callbacks
have separate ownership, so no `fenced:true` attestation is made here.

F031 still needs attention/mail/calendar/list sources. F034 still needs the
intent/time/policy/funding gates. Neither later routine slice is enabled or
accepted by this support increment. Exact-SHA publication and deployment receipts
are tracked in the owner thread; source publication is not live readiness.
