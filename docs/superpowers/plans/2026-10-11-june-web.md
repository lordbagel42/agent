# June conversation web UI implementation plan

**Goal:** Deliver the conversation-first SvelteKit direction from the Bops exploration as a real, owner-authenticated Slack companion, not another mockup.

**Architecture:** SvelteKit prerenders the credential-free shell; June's existing Hono host authenticates every page, asset and JSON request using its console session. A read-only Effect service reads Slack under the configured bot identity, checks the owner's current membership, and projects only messages, authors and file metadata. No actor history, worker prompts, new storage schema, second agent runtime or new Slack scopes.

**Scope decision:** This independently usable first increment is owner-only and read-only. Private means the owner's one-to-one Slack DM with June; group DMs and channels remain shared. Shared conversations are June's existing subscribed threads. Replies use an explicit Open in Slack action; attributed web posting, participant accounts and editing artifacts require a later increment, not simulated controls. Existing retained Slack history, not June's reasoning context, is the transcript source.

OWN-WORLD: Extend June's existing #111111 / #181818 neutral surfaces, system sans, hairline rules and white primary action. No imagery or copied Bops code.

FIRST VIEWPORT: A 56px app header above a 264px conversation rail, a flexible chronological message pane, and an optional 288px inspector. On narrow screens, the rail and inspector become separate views with labelled back controls. Scope and source remain visible above the messages.
