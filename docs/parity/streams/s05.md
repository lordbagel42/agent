## First source contract — 10 October 2026

The execution-only `s05.task-inspection` command accepts
`{action:"inspect",id:"workflow:<64-character lowercase runId>"}`. It consumes
K7 `TaskViewPort` through the named `tasks` host port and defaults on only within
the existing source, role, capability-ceiling and software-activation boundaries.
Absent integration stays unavailable. An explicit disable remains disabled.

`createTaskViewProjection()` returns `{tasks,observePresentation}`. S14's existing
workflow owner supplies `WorkflowDependencies.observePresentation(snapshot,readable)`
after its own durable save, without an inspection triggering that save. The
snapshot contains only `runId`, `revision`, `status`, `operationStatuses`,
`capturedAt`, `deletionRevision` and exact `sourceScope`. Its synchronous reader
guard checks the publication generation and live actor incarnation, original
source authority, exact authenticated requester/conversation/thread and deletion.
The guard must not retain private source/input/result bodies after actor sleep.
Existing authority checks can read synchronous SQLite-backed stores; in particular,
the current deletion-revision reader loads its existing ledger snapshot. No-wake
does not mean pure or no-I/O, and these checks must not be weakened. This adds no
store and does not reconstruct workflow state from raw KV.

The projection keeps at most 128 process-local metadata entries, expires them
60 seconds after the owner's capture, and prunes on access/publication. Reads do
not refresh observation time or cache priority. Restart, eviction, expiry,
sleep/inactive source and missing observations stay unavailable/unknown. No
durable schema, cache backfill, workflow actor creation/wake, timer or raw-KV
fallback exists. The existing worker authorization/delivery RPC fences still run.
Expiry is a visibility limit, not guaranteed memory erasure while the cache is idle.
C02 owns the named binding and dispatch fences; C01 connects the same instance's
producer and task port only when the workflow producer is present and enabled.
No unreviewed owner-local workflow changes are imported.

The projection emits an opaque exact-source fingerprint, owner/run reference,
recognized lifecycle state and bounded raw receipt-status counts. Journal wrapper
and step entries can describe one effect, so counts are not effect counts.
Operation names are not provider operation IDs: `operationIds` stays empty.
No source, names, arguments, results, error bodies or report text are retained or
returned. Delivery remains `unknown` without a linked delivery receipt, including
after a completed run or a notify-named operation.

Failed and cancelled runs remain distinct. A completed source with any observed
started, failed, not-started, unknown or unrecognized receipt becomes `unknown`,
not complete. `needs_review` with uncertain, started or absent receipts stays
unknown; known terminal receipts can describe a block. Aggregate completion,
cancellation and absent/pruned history never attest fencing, settlement, reversal
or safe resource reassignment. The original owners retain those responsibilities.

Observation freshness begins at the owner's capture and expires after 60 seconds.
Expired or future-dated evidence is unavailable/unknown. Definition revisions are
not loaded Git revisions; the loaded-revision field remains null without an
independent runtime identity. Missing, denied, revoked, deleted and unreadable
work use the same unavailable result, without revealing foreign existence.

All four K8 sections explain triggers, missing prerequisites, continuation owners,
source and role limits, inspection, cancellation and unknown-outcome rules.
Interaction delegates only when a worker is available; execution uses the exposed
command; event-decision and notification turns gain no action from the guidance.
Inspection adds no provider call, enrollment, charge, retention, retry or poller.
The owner's 13:47 policy clarification prohibits autonomous purchases, orders,
transfers and new financial commitments, not configured inference or built-in
tool use. Those tools need no per-account billing/no-charge attestation or new
artificial token/dollar admission cap. Runtime knowledge preserves real permissions,
privacy, cancellation and provider quotas/rate limits; S05 adds no billing gate.

span multiple conversations. Returned scope uses the original workflow owner's
exact-source digest, not the broad audience alone. This fingerprint is neither
an access token nor an actor lookup key. The review also required checking the
reader's actor lifecycle, not just its read-only action body.

C02's version-pinned audit, independently confirmed with upstream source, found
that RivetKit 2.3.21 `get(key)` avoids creation but an action RPC still wakes a
sleeping actor and resumes its workflow. The [client handle](https://github.com/rivet-dev/rivet/blob/v2.3.21/rivetkit-typescript/packages/rivetkit/src/client/client.ts#L270-L308)
does not return a state snapshot; the [gateway](https://github.com/rivet-dev/rivet/blob/v2.3.21/engine/packages/guard/src/routing/pegboard_gateway/mod.rs#L531-L560)

Consequently the original `presentation(context.event)` reader proposal was
rejected before publication/mounting. It is not the task reader, even with an
authenticated event. The eventless artifact-viewer exception, raw workflow
inspection and mutating worker/research summaries are not alternatives.
