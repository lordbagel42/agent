# S19 — environments and coding handoff

## Local coding cancellation fences — 10 October 2026

This increment supports F002/F071 without claiming full cross-owner intent
cancellation. The existing coding actor owns the exact proposal and attempt;
its synchronous currentness check follows preparation and persistence through
native/remote dispatch and verifier launch. Cancellation/revocation mutates
that owner before its existing save and abort. Late received evidence remains
inspectable, while stale verification continuation and notification are denied.

No journal names/order, runtime selection, timeout/lifecycle wrappers, fallback,
schema migration or new effect authority are introduced. Remote SSH cancellation
is observation cancellation, never proof the remote agent stopped. Unknown
worker/verifier capacity and started verification receipts remain held for
reconciliation. Results arriving after an abort already won the existing race
are not newly collected by this increment.

Disposable offline probes exercise actual adapters with intercepted provider
boundaries and a real local worktree/verifier. Before the change, stale work
reached remote SSH, Codex/Pi process admission and verifier launch after fsync.
After the change those boundaries deny dispatch; a current local verifier still
runs and records a matching source receipt. Existing Claude and Codex post-thread
save checks and Amp's initial guard also pass. No provider, SSH, inference or paid
compute call is made by those probes, and no ordinary tests are committed.

June receives the local cancellation and unknown-outcome rules through S19's
interaction, execution, event-decision and notification-only knowledge slot.
Source support is not loaded deployment or a live coding-provider attestation.

The published K2 begin/settle signatures do not yet have a root implementation.
Remaining integration: C02 host-created origin/intent propagation for all coding
producers, root cancellation, descendant acknowledgement and delivery.
No async `current()` RPC may replace the
synchronous provider-boundary check, and legacy proposals must not receive
fabricated new intent authority. C02's proposed atomic `intentBinding` must keep
the root reference and original conversation/event/delegation provenance
together; coding job IDs are not original intent IDs. The root adapter and C01
provenance type freeze remain prerequisites, not implemented support in this
increment.

## E2B no-spend admission — 10 October 2026

The actual E2B adapter consumes S04's published synchronous `spendingAdmission`
contract and classifies its external provisioning as `owner-funded`. Both
availability and direct/queued run admission deny it under current policy.
The run returns `owner_spending_prohibited` and the policy reason before any
lease, allocation, SDK dispatch or cleanup work. `cleanup:not_needed` describes
only this denied attempt; it cannot settle older uncertain provider work.
Credentials, enabled configuration, claimed credits and model input cannot
change the classification. No paid fallback is introduced or exercised.

The disposable probe first reproduced an attempted allocation with the SDK
replaced by a throwing sentinel and network disabled. After the guard it observes
zero allocation attempts, repeated safe denial, unchanged missing-configuration,
invalid-request, cancellation and unsupported-environment diagnostics, and the
decoded denial in June's bounded result format. Real local QuickJS computation
still returns the independently expected `[19,-30,75]`. All five actual
`buildModelRequest` paths include the blocked-state knowledge, even when E2B is
unavailable; notification/completion remain unable to start compute. No real
`Sandbox.create`, provider request, inference or paid fallback ran.

Oracle found no production-code blocker; its probe-only formatting assertion
finding was verified and corrected to decode the existing escaped JSON. This
slice does not cap included inference, attest arbitrary compute as free, enable
BoxLite, prove global funding enforcement or constitute live activation. Only
June's app changes; no companion installation is required.
